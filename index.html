A / AGENTS & WORKFLOW AUTOMATION · CLONEFORCE

Sounds simple.
Until the calendar changes.

I independently built an end-to-end scheduling capability within an existing AI-assistant platform: from processing a conversational request to creating the event, invitations, and confirmation emails.

PythonCalendar APIsOAuthAgent tools

Try the idea / illustrative simulation

The implementation, not just the animation

What I owned

I wrote the Python scheduling functions from request interpretation through calendar operations, meeting links, invitations, and confirmation emails. The platform supplied conversation context, date/time information, and communication infrastructure.

Where the judgment lives

The workflow handled participants, relative dates, duration, time zones, working hours, and agenda details. After an external participant replied, it checked availability again and proposed alternatives if the selected time was no longer available.

Code and prompts had different jobs

Scheduling decisions and operations were implemented in Python. System prompts primarily guided skill invocation and agent behavior. Users authorized calendar access; external calendars weren’t assumed to be directly accessible.

Beyond the prototype

The capability was demonstrated to prospective customers and used internally to arrange meetings. My work also included Salesforce API-connected automation and integration documentation.

B / DOCUMENT INTELLIGENCE · INDEPENDENT PROJECT

A plausible answer isn’t the finish line.

I built a Python RAG prototype with Ollama and ChromaDB: ingestion, chunking, embeddings, semantic search, and metadata filtering. Diagnostic scripts helped investigate missing context and unsupported responses.

A point of view

What is worth building?

I work with AI, but I don’t think every possible use is a worthwhile one. I’m interested in applications that support healthcare, scientific discovery, and useful everyday work.

I also care about what we choose not to automate—and where human creativity should remain central.

I want to build with a sense of purpose, not simply because something can be generated.

Another question I’m carrying

Which problem is worth going all in on?

I’m exploring the overlooked friction in everyday work, and which problem I might eventually build a business around. I haven’t chosen the one yet.
